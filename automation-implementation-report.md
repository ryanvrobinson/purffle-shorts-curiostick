## 4. Production automation details

### Daily automation controller — `purffle_shorts/automation.py` (implemented)
- `DailyAutomation` runs **at most one video per day**.
- `RunLock`: file-based exclusive lock (`fcntl.flock` on Linux, `msvcrt.locking` on Windows) preventing overlapping runs; context-manager support.
- `DailyRunTracker`: `daily_runs` table in `data/history.db` with columns `run_date (YYYY-MM-DD, UNIQUE)`, `started_at`, `completed_at`, `status (running|completed|failed|skipped)`, `video_id`, `error`, `quality_gate_passed`, `uploaded`, `instagram_published`.
- Duplicate-run prevention: `has_completed_run_today()` short-circuits if today already completed.
- Run lifecycle: record start → generate video via `Studio.make()` → quality gate (`QualityGate`) → optional YouTube upload → optional Instagram publish → record completion/failure/skip.
- `dry_run=True`: verifies config only, no generation/upload; marks run completed.
- `_verify_config()`: warns if no LLM provider, no TTS engine, no visual sources, or upload enabled without `credentials.json`.
- `cmd_daily` (cli.py:515): `skip_upload=True` **always** — daily runs stop at review and never publish; `skip_instagram=True` unless `--instagram` is passed; `--dry-run`, `--skip-quality`, `--skip-upload` (deprecated) flags available.

### Production configuration (config.py defaults, overridable via env/CLI)
- `upload=False` — videos stay in review until explicitly uploaded.
- `privacy=public`, `publish_times=[]` (scheduling slots like `09:00,14:00,19:00`), `timezone=Asia/Kolkata`, `daily_upload_limit=6`.
- `synthetic_media=True` — YouTube altered/synthetic content disclosure.
- `script_review=rewrite`, `script_quality_threshold=70` — Script Doctor second pass.
- `research_verify=False` — claim-based fact verification off by default.
- `tts_engine=edge`, `target_seconds=40`, `resolution=1080x1920`, `fps=30`, `aspect=9:16`.
- `visual_sources=[pexels, pixabay]`, `visual_choice=stock-first` (suitability and ai-first available).

### Scheduling
- Production cadence: once daily at 08:30 UTC via the GitHub Actions cron schedule (curiostick-daily.yml), plus manual `workflow_dispatch`.
- Local equivalent: `python -m purffle_shorts daily --verbose` (see deployment instructions, section 8).

## 5. YouTube and Instagram publishing requirements

### YouTube (implemented; manual review required)
Module: `purffle_shorts/youtube.py`
- **OAuth:** Interactive `purffle-shorts auth` once per channel; `credentials.json` (desktop OAuth client, YouTube Data API v3 enabled) → `token.json` (chmod 600). Legacy `token.pickle` from 1.x is migrated.
- Scopes: `youtube.upload` (+ `youtube` manage if a playlist is set; `youtube.readonly` for stats).
- **Explicit PUBLISH confirmation:** `upload --id N` / `upload --pending` runs `_review_upload()` (cli.py:267) which prints title, file, visibility, scheduled slot, metadata, narration, captions, visual sources, source references, research warnings, quality-check results, then requires the operator to type `PUBLISH`. Without that exact input, nothing is uploaded or scheduled.
- Resumable chunked upload (8 MiB chunks) with exponential backoff (max 8 retries) on 500/502/503/504 and connection errors; `quotaExceeded`/`uploadLimitExceeded` surfaced as `QuotaExceeded`.
- Scheduled publishing into `PUBLISH_TIMES` slots (≥15 min from now, skipping taken slots, 60-day horizon); playlists; `made_for_kids`; `containsSyntheticMedia` disclosure when `synthetic_media=true`.
- One upload at a time (thread lock; the API client is not thread-safe).
- Daily automation leaves YouTube upload off (`UPLOAD=false`, `skip_upload=True`); a human must run `upload` after review.

### Instagram Reels (UNIMPLEMENTED / stub)
Module: `purffle_shorts/instagram.py`
- `publish_reel(settings, result)` is a **placeholder**: it logs "Instagram Reels publishing not fully implemented - requires video hosting", builds a caption from metadata, and **returns `False`**. Internally `_create_media_container` raises `NotImplementedError`.
- The Meta Graph API requires the video to be hosted at a publicly accessible URL; the file:// approach in the stub will not work. A CDN upload or Meta resumable-upload endpoint must be implemented for production use.
- Requirements documented in the module (not yet wired): Instagram Professional Account (Business/Creator), Meta App with Instagram Graph API access, long-lived access token with `instagram_graph_user_profile`, `instagram_graph_user_media`, `instagram_content_publish`; env vars `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`, `INSTAGRAM_USER_ID`, `INSTAGRAM_ACCESS_TOKEN`.
- In automation, Instagram publishing is skipped by default (`skip_instagram=True`) and only attempted when `--instagram` is passed **and** `is_instagram_configured()` returns true — which it cannot until the four INSTAGRAM_* env vars are set and `publish_reel` is implemented.

## 8. Deployment instructions (no source changes, no commit/push)

**Local first run:**
1. Copy `.env.example` to `.env` and fill in at least one LLM key (or set `LLM_PROVIDER=ollama`/`custom`). Do not commit `.env` (it is gitignored).
2. Install ffmpeg and fonts (`sudo apt-get install -y ffmpeg fonts-dejavu-core` on Ubuntu).
3. `pip install -e ".[dev]"` (or use the provided `.venv`).
4. `python -m purffle_shorts doctor` — verify ffmpeg, LLM, voices, keys, YouTube setup.
5. `python -m purffle_shorts daily --dry-run` — config-only verification, no generation.
6. `python -m purffle_shorts daily --verbose` — produces one video, runs the quality gate, stops before any upload (daily runs never publish by default).
7. To publish: `purffle-shorts auth` (OAuth once), then `purffle-shorts upload --pending` and type `PUBLISH` for each reviewed video.

**GitHub Actions production scheduling:**
1. Add the four secrets to the repository: `NVIDIA_NIM_API_KEY`, `NVIDIA_NIM_MODEL`, `PIXABAY_API_KEY`, `AGNES_API_KEY`.
2. Ensure `.github/workflows/curiostick-daily.yml` is on the default branch (currently untracked — add and commit it).
3. The workflow runs daily at 08:30 UTC (14:00 IST) and can be triggered manually via `workflow_dispatch`.
4. Uploads remain disabled (`UPLOAD=false`); artifacts (`output_videos/`, `data/logs/`) are retained for 1 day for inspection.

**Release pipeline (no action needed unless cutting a release):**
- Tag and release on GitHub → `release.yml` builds, publishes to PyPI via Trusted Publishing, registers the MCP server, and pushes the Docker image to GHCR.
